Key Observations

  • All primary keys are UUID v4 strings (VARCHAR 36) — never auto-increment integers
  • STUDENTS has four denormalized columns: class_name, section_name, teacher_name, teacher_cnic — intentional 3NF violation for UX (see Normalization diagram)
  • QUEUE_ENTRIES.booking_id is UNIQUE — each booking can appear in the queue at most once
  • USERS.section_id is nullable — only teachers are assigned to a section
  • PARENTS is an extension of USERS (one-to-one) via user_id FK — role-based profile pattern
  • ||--o{ means "one to zero-or-many" (one BRANCH has many CLASSES)
  • ||--o| means "one to zero-or-one" (one USER has at most one PARENT profile)
  • |o--o{ means "zero-or-one to zero-or-many" (SECTION is optional for USERS)
