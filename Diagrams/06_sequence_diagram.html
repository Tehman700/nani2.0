Sequence Diagram

Message-sequence diagrams for the two core flows: User Login and Book a Pickup with live queue broadcast.

Flow 1 — User Login (JWT Authentication)
sequenceDiagram actor User as User (Browser) participant FE as React Frontend participant API as FastAPI participant DB as MySQL User->>FE: Enter email + password, click Login FE->>API: POST /auth/login {email, password} API->>DB: SELECT * FROM users WHERE email=? DB-->>API: user row (hashed_password, role) API->>API: bcrypt.verify(password, hashed_password) alt Credentials valid API->>API: jwt.encode({sub: user_id, role: role}) API-->>FE: {access_token, token_type: "bearer"} FE->>FE: localStorage.setItem("token", access_token) FE->>FE: Redirect to /dashboard or /teacher-queue FE-->>User: Dashboard loaded else Invalid credentials API-->>FE: 401 Unauthorized FE-->>User: "Invalid email or password" end
Flow 2 — Book a Pickup + Live Queue Broadcast
sequenceDiagram actor Parent as Parent (Browser) participant FE as React Frontend participant API as FastAPI participant DB as MySQL participant Redis as Redis Pub/Sub participant WS as WebSocket Manager actor Teacher as Teacher (Browser) Parent->>FE: Open "Book a Pickup" form FE->>API: GET /student/my-kids (Bearer token) API->>DB: SELECT students WHERE parent_id=? DB-->>API: [list of children] API-->>FE: [{id, name, section_id, ...}] FE-->>Parent: Show child selector + date/time picker Parent->>FE: Select child, pick date & time, submit FE->>API: POST /booking/create {student_id, pickup_time} API->>API: Decode JWT → get parent_id API->>DB: SELECT student WHERE id=? DB-->>API: student {section_id, ...} API->>API: Calculate priority_score API->>DB: INSERT INTO bookings (id, student_id, parent_id, pickup_time, status="pending", priority_score) DB-->>API: booking saved API->>DB: INSERT INTO queue_entries (booking_id, section_id, position) DB-->>API: queue entry saved API->>Redis: PUBLISH queue:{section_id} {booking_id, student_name, position, status} Redis-->>WS: Deliver message to subscribers API-->>FE: {booking_id, status: "pending", position: N} FE-->>Parent: "Booking confirmed — Queue position #N" Note over Redis,WS: Real-time broadcast to all section listeners Teacher->>FE: Connected via WebSocket ws://localhost:8000/ws/teacher/{cnic} WS-->>Teacher: Queue update pushed instantly Teacher->>FE: Clicks "Mark as Picked Up" FE->>API: PATCH /booking/{id}/status {status: "picked_up"} API->>DB: UPDATE bookings SET status="picked_up" WHERE id=? DB-->>API: updated API->>Redis: PUBLISH queue:{section_id} updated payload Redis-->>WS: Broadcast to parent + teacher FE-->>Parent: Live queue updates — student removed from queue

Key Implementation Details

  • JWT — HS256 algorithm, encoded with SECRET_KEY; decoded on every protected endpoint via FastAPI Depends()
  • priority_score — float calculated as time difference between booking creation and requested pickup_time; earlier bookings get lower (better) scores
  • Redis channels — queue:{section_id} for parent queue views, teacher:{cnic} for teacher queue page
  • WebSocket — clients subscribe on page load via ws:// connection; FastAPI pushes on every booking change
  • Queue position — computed from ORDER BY priority_score ASC on queue_entries for the section
  • No polling — all live updates are push-based through Redis → WebSocket; zero frontend polling loops
