Normalization

Analysis of 1NF, 2NF, and 3NF compliance across all 9 tables — including the intentional 3NF violation in the students table.

✓ PASS
First Normal Form (1NF)
Every column must contain atomic values; no repeating groups; each row is uniquely identifiable.

All 9 tables satisfy 1NF. Every column stores a single, indivisible value. There are no multi-valued attributes, no arrays stored in columns, and no comma-separated lists. Each table has a single-column UUID primary key that guarantees row uniqueness.

The photo_url column in students stores a Base64-encoded string or URL as a single text value — this is atomic. The role and status columns are ENUM types that store a single string value per row.

Second Normal Form (2NF)
Must be in 1NF. Every non-key attribute must depend on the entire primary key (no partial dependencies).

All 9 tables satisfy 2NF. 2NF is only relevant when a table has a composite primary key. Since every table in this schema uses a single-column UUID primary key, partial dependency cannot exist by definition — there is no part of the PK to partially depend on.

This design choice (single-column UUID PK on all tables, rather than composite natural keys) automatically satisfies 2NF across the entire schema.
